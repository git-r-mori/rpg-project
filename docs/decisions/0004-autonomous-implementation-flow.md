# 0004: エージェントによる自律的な実装フロー

- ステータス: 採用
- 日付: 2026-10-13
- [ADR 0003](0003-branch-strategy-and-commit-convention.md) の「AI エージェントは、ユーザーの指示があったときだけコミット・プッシュ・プルリクエスト作成を行う」を置き換える。

## 背景

ADR 0003 では、エージェントはユーザーの指示があったときだけコミット・プッシュ・プルリクエスト作成を行うとした。しかし実装のたびにこれらを個別に指示するのは手間がかかり、テストの書き方や検証の手順も依頼ごとにぶれやすい。エージェントが依頼の分析からプルリクエストの作成までを一定の手順で進め、人間はレビューとマージに集中できるようにしたい。

## 決定

実装タスクでは、エージェントが次のフローに従い、Draft プルリクエストの作成から Ready への切り替えまで自律的に行う。手順の正本は `.cursor/rules/implementation-flow.mdc`（英語）とする。

1. 分析・調査: 要件を詳細まで落とし込み、修正対象のファイル一覧と変更方針の概要を提示して、ユーザーの承認を待つ。
2. 計画: 差分量（目安 500 行）に応じてプルリクエストの分割を検討する。分割する場合は提案して承認を待ち、前のプルリクエストのマージ後に最新の `main` から次に着手する。
3. ブランチ作成: 未コミットの変更があれば中断して報告する。最新の `main` から作業用ブランチを作る。
4. Red: 空の関数と型だけを先に用意し、テストがアサーションで失敗することを確認する。
5. Green と整理: 最小限の実装でテストを通したあと、リファクタリング、JSDoc、関連ドキュメントの整備まで行う。
6. 検証とコミット: `pnpm verify` を実行する。失敗したら最大 3 回まで修正して再実行し、それでも通らなければ中断して報告する。
7. Draft プルリクエスト: `AGENTS.md` の手順でプッシュし、Draft プルリクエストを作成する。
8. CI と Ready 化: `.github/workflows/` がなければそのまま Ready にする。CI がある場合は、すべて通ったら Ready にする。自分の変更が原因の失敗は 1 回だけ修正を試みる。不安定なテストやインフラなど変更と無関係な失敗は、修正せず失敗ジョブを 1 回だけ再実行し、それでも失敗したら報告する。

完了時の報告はプルリクエストの URL のみとし、中断したときは理由を報告する。マージは人間が行う。

振る舞いを変えない変更（ドキュメント、設定、文言の修正など）と、ユーザーがフロー不要と明示した場合は、フロー全体を省略してユーザーの指示に従う。省略した場合も、`main` に直接コミットしないなどの GitHub Flow のルールは守る。

## 検討した代替案

- ADR 0003 のまま、指示があったときだけコミット・プッシュ・プルリクエスト作成を行う: 誤った変更が共有される心配はないが、依頼のたびに指示が必要で、手順もそろわない。
- 承認を待たず、分析から Ready 化まで完全に自動で進める: 最も速いが、方針のずれに気づくのがプルリクエスト作成後になり、手戻りが大きい。そのため、実装前の方針提示とプルリクエスト分割の提案では承認を待つことにした。

## 影響

- `AGENTS.md` の Git workflow 節と `.cursor/rules/00-project-core.mdc` を、自律的にプルリクエストを作成する方針に更新し、プルリクエスト作成手順を `AGENTS.md` に追記した。
- CI はフェーズ 4 で導入するため、それまでは手順 8 で CI の確認をせずに Ready にする。
