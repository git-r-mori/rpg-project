# 0004: エージェントによる自律的な実装フロー

- ステータス: 採用
- 日付: 2026-10-13
- [ADR 0003](0003-branch-strategy-and-commit-convention.md) の「AI エージェントは、ユーザーの指示があったときだけコミット・プッシュ・プルリクエスト作成を行う」を置き換える。

## 背景

ADR 0003 では、エージェントはユーザーの指示があったときだけコミット・プッシュ・プルリクエスト作成を行うとした。しかし実装のたびにこれらを個別に指示するのは手間がかかり、テストの書き方や検証の手順も依頼ごとにぶれやすい。エージェントが依頼の分析からプルリクエストの作成までを一定の手順で進め、人間はレビューとマージに集中できるようにしたい。

## 決定

実装タスクでは、エージェントが決まったフローに従い、依頼の分析から Draft プルリクエストの作成、CI 通過後の Ready への切り替えまで自律的に行う。手順の正本は `.cursor/rules/implementation-flow.mdc`（英語）とし、この ADR には手順を書き写さない。

フローの骨格は次のとおり。

- 人間の承認を挟むのは、実装前の方針提示と、プルリクエスト分割の提案の 2 か所だけとする。
- テストを先に書き（Red）、最小限の実装で通してから整理する（Green とリファクタリング）。
- `pnpm verify` と CI の失敗には、回数の上限を決めて対処し、上限を超えたら中断して報告する。
- マージは人間が行う。

振る舞いを変えない変更と、ユーザーがフロー不要と明示した場合は、フローを省略する。省略した場合も、`main` に直接コミットしないなどの GitHub Flow のルールは守る。

## 検討した代替案

- ADR 0003 のまま、指示があったときだけコミット・プッシュ・プルリクエスト作成を行う: 誤った変更が共有される心配はないが、依頼のたびに指示が必要で、手順もそろわない。
- 承認を待たず、分析から Ready 化まで完全に自動で進める: 最も速いが、方針のずれに気づくのがプルリクエスト作成後になり、手戻りが大きい。そのため、実装前の方針提示とプルリクエスト分割の提案では承認を待つことにした。

## 影響

- `AGENTS.md` の Git workflow 節と `.cursor/rules/00-project-core.mdc` を、自律的にプルリクエストを作成する方針に更新し、プルリクエスト作成手順を `AGENTS.md` に追記した。
- CI はフェーズ 4 で導入するため、それまでは手順 8 で CI の確認をせずに Ready にする。
